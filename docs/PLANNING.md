# Not Today — 서비스 기획서 (v0.2)

> 오늘은 아니야.
> "무엇을 할지"가 아니라 "무엇을 하지 않을지"를 정하고, 지켜냈는지 기록하는 서비스.

---

## 1. 문제 정의

Todo List는 "더 많이 하기"를 전제로 한다. 하지만 실제로 하루를 망치는 건
할 일을 못 한 것보다 **하지 말아야 할 행동을 반복한 것**인 경우가 많다.

- 자기 전 침대에서 숏폼 보기
- 점심 먹고 습관적으로 디저트 먹기
- 회의 중 노트북 열고 딴짓하기
- 퇴근 후 "잠깐만" 하고 게임 켜기

이런 행동은 Todo 앱에 넣을 수 없다. "하지 않기"는 체크박스로 표현되지 않고,
성공의 순간이 없기 때문이다. 하루가 끝나야 "안 했다"를 알 수 있다.

**핵심 인사이트**
1. 하지 않기는 "완료"가 아니라 **"하루 동안 유지"**의 개념이다.
2. 실패는 "안 함"이 아니라 **"해버림"**이다. 실패의 순간이 명확하다.
3. 그래서 UI의 기본 상태는 **"지키는 중"**이어야 하고, 사용자는 실패했을 때만 손을 댄다.
4. **"얼마나"는 중요하지 않다.** 게임을 3시간 대신 2시간 했다고 지킨 게 아니다.
   켰으면 어긴 것이다. 이 서비스는 시간이나 횟수를 재지 않고, **했는지 안 했는지만** 묻는다.

## 2. 타겟 사용자

| 페르소나 | 상황 | 하지 않고 싶은 것 |
|---|---|---|
| 직장인 A (29) | 퇴근 후 시간이 증발함 | 퇴근 후 유튜브 자동재생, 야식 배달 |
| 대학원생 B (26) | 집중력 관리가 과제 | 연구 중 SNS, 밤샘 |
| 프리랜서 C (34) | 일과 휴식 경계가 없음 | 주말에 슬랙 확인, 견적 없이 일 받기 |
| 자기계발형 D (31) | Todo 앱은 이미 씀, 습관 앱도 씀 | 충동구매, 남 험담 |

공통점: **이미 무엇을 하지 말아야 하는지 알고 있다.** 몰라서가 아니라 "선언하고 추적할 곳"이 없어서 못 지킨다.

## 3. 핵심 가치 제안

**"오늘 하지 않을 것을 아침에 선언하고, 밤에 지켜냈는지 확인한다."**

세 가지 차별점:

1. **역전된 체크박스** — 기본이 ✅(지키는 중). 사용자가 어기면 ❌로 바꾼다. 아무것도 안 하면 성공이다.
2. **연속 기록(Streak)이 아닌 "방어 일수"** — "N일째 안 함". 실패해도 0으로 리셋되는 대신 "이번 달 24/30일 방어"처럼 비율로 보여준다. 리셋의 좌절감을 줄인다.
3. **실패 기록이 데이터가 된다** — 어겼을 때 "언제, 왜(트리거)"를 한 줄로 남긴다. 축적되면 "나는 주로 밤 11시 이후, 피곤할 때 무너진다"가 보인다.

## 4. 기능 범위

### 4.1 MVP (1차 출시)

| # | 기능 | 설명 |
|---|---|---|
| F1 | Not-Todo 항목 생성 | 제목, (선택) 이유, (선택) 적용 요일 |
| F2 | 오늘 화면 | 오늘 적용되는 항목 목록. 기본 상태 "지키는 중" |
| F3 | 어김 기록 | 확인 한 번으로 "어겼음" 처리. 시각 자동 기록, 한 줄 메모 선택. **항목당 하루 1회, 되돌리기 없음** |
| F4 | 하루 마감 | 하루 시작 시각 기준 자동 확정. 어김 없으면 "방어 성공" |
| F5 | 항목별 통계 | 방어율(최근 7일/30일), 총 어긴 날 수, 어긴 시간대 분포 |
| F6 | 항목 보관/삭제 | 더 이상 추적 안 하는 항목은 보관 (기록은 유지) |
| F7 | 로컬 우선 저장 | 로그인 없이 시작. 데이터는 기기에 저장 |

어김 기록 원칙:
- 한 번 어겼으면 그날은 끝이다. 두 번째 어김은 기록하지 않는다 (2차에서 허용 검토).
- 취소 기능은 없다. 실수 탭은 확인 시트("정말 어겼나요?")로 막는다.
  취소가 있으면 "아까 건 취소하고 싶다"는 협상이 생긴다.

### 4.2 2차 (검증 후)

- 계정 + 동기화 (여러 기기)
- 리마인더: "취약 시간대"에 맞춰 알림 ("지금이 보통 무너지는 시간이에요")
- 주간 회고 카드: 이번 주 방어율, 가장 자주 어긴 항목, 주요 트리거
- 항목 템플릿: 자주 쓰는 Not-Todo 추천 (숏폼, 야식, 충동구매 등)
- 어김 시 "대신 한 것" 기록 (대체 행동 유도)
- 하루 여러 번 어김 기록 (통계는 여전히 "어긴 날" 기준, 횟수는 참고 정보)

### 4.3 의도적으로 하지 않을 것 (이 서비스의 Not-Todo)

- **Todo 기능 추가** — 정체성이 흐려진다. 절대 넣지 않는다.
- **소셜/공유/랭킹** — 하지 않기는 사적인 영역. 비교는 동기가 아니라 수치심을 만든다.
- **게이미피케이션(뱃지, 레벨)** — 방어율이라는 단순한 숫자 하나면 충분하다.
- **긴 온보딩** — 첫 실행 후 30초 안에 첫 항목을 만들 수 있어야 한다.
- **시간/횟수 측정** — "하루 30분 이하", "주 2회까지" 같은 허용치는 만들지 않는다.
  허용치는 협상의 여지를 만들고, 협상은 결국 어김으로 이어진다. 답은 했다/안 했다 둘뿐이다.

## 5. 핵심 사용자 흐름

### 5.1 첫 실행
```
앱 실행 → "오늘 하지 않을 것 하나만 적어보세요" 입력창
→ 항목 생성 → 오늘 화면 (항목 1개, 상태: 지키는 중)
```

### 5.2 하루 중
```
오늘 화면 진입 → 모든 항목 "지키는 중"
→ (어겼을 때) 항목 탭 → "정말 어겼나요?" 확인 → (선택) 한 줄 메모
→ 항목 상태 ❌ + 시각 표시. 이후 그날은 해당 항목 탭 불가 (잠김)
```

### 5.3 하루 마감
```
자정 → 당일 기록 확정
→ 다음날 첫 진입 시 어제 요약 토스트: "어제 3개 중 2개 방어"
```

### 5.4 통계 확인
```
항목 탭 → 상세 화면
→ 방어율 (7일 / 30일), 최근 어김 목록 (시각 + 메모), 시간대 히트맵
```

## 6. 화면 구성

| 화면 | 주요 요소 |
|---|---|
| **오늘(Today)** | 날짜, 오늘 방어 현황(2/3), 항목 카드 리스트, + 버튼 |
| **항목 카드** | 제목, 상태(지키는 중 / 어김 HH:MM), 방어 일수 뱃지 |
| **어김 기록 시트** | "정말 어겼나요?" 확인, 한 줄 메모, 저장 |
| **항목 상세** | 방어율, 어김 히스토리, 시간대 분포, 편집/보관 |
| **항목 편집** | 제목, 이유, 적용 요일, 보관/삭제 |
| **전체 통계** | 이번 달 종합 방어율, 항목별 랭킹, 취약 시간대 |
| **설정** | 하루 시작 시각(예: 새벽 4시 기준), 테마, 데이터 내보내기 |

UI 원칙:
- 기본 화면은 조용해야 한다. 지키고 있으면 아무 일도 안 일어난다. 캐릭터만 편안하게 숨 쉰다.
- 어김 처리는 1탭 + 1확인. 죄책감을 주는 카피 금지. 캐릭터가 대신 말한다. ("아… 오늘은 아니었네. 내일 다시.")
- 색상: 지키는 중 = 따뜻한 크림/세이지, 어김 = 부드러운 레드. 공격적인 색은 쓰지 않는다.
- 자세한 비주얼/모션 방향은 14장.

## 7. 데이터 모델

```
NotTodo
  id            string (uuid)
  title         string
  reason        string?         // 왜 하지 않으려는지
  activeDays    int[]           // 0(일)~6(토), 비어있으면 매일
  createdAt     datetime
  archivedAt    datetime?

Violation                        // 어김 기록
  id            string
  notTodoId     string
  date          date            // 하루 시작 시각 기준의 "그날"
  occurredAt    datetime
  note          string?
  trigger       string?         // 2차: 태그 (피곤함, 스트레스, 심심함...)
  // MVP: (notTodoId, date) 유니크. 2차에서 여러 번 허용 시 제약만 푼다.

DailyRecord                      // 하루 마감 시 확정 (통계 캐시)
  date          date
  notTodoId     string
  defended      boolean
```

- "오늘"의 기준은 자정이 아니라 사용자가 설정한 **하루 시작 시각** (기본 04:00).
  새벽 1시의 어김은 "어제"로 기록되어야 자연스럽다.
- `DailyRecord`는 파생 데이터. `Violation`으로부터 언제든 재계산 가능해야 한다.

## 8. 기술 스택

**플랫폼 결정: Android + iOS 동시 출시. 웹앱을 네이티브 셸로 감싼 웹뷰 방식.**

| 영역 | 선택 | 이유 |
|---|---|---|
| 웹앱 | Vite + React + TypeScript | SPA 하나를 두 플랫폼에 그대로 탑재. SSR 불필요 |
| 네이티브 셸 | Capacitor | 웹뷰 래핑의 표준. 알림/로컬 저장/앱 생명주기 플러그인 제공 |
| 스타일 | Tailwind CSS | 빠른 프로토타이핑, safe-area 대응 쉬움 |
| UI 모션 | Motion (구 Framer Motion) | 스프링 물리 기반. 오버슈트/바운스로 "텐션" 구현 |
| 캐릭터 애니메이션 | Rive | 상태머신 기반 인터랙티브 캐릭터. 파일 하나로 idle/어김/축하 상태 전환 |
| 상태/저장 | Zustand + SQLite (Capacitor 플러그인) | 로컬 우선. 웹뷰 스토리지보다 안정적이고 OS가 임의로 지우지 않음 |
| 2차 백엔드 | Supabase (Auth + Postgres) | 동기화 도입 시 최소 비용 |
| 테스트 | Vitest + Playwright | 날짜 경계(하루 시작 시각) 로직은 유닛 테스트 필수 |
| 빌드/배포 | GitHub Actions → TestFlight / Play 내부 테스트 | |

웹뷰 방식 주의점:
- **하루 마감 처리**는 앱이 꺼져 있어도 일어나야 한다. 자정 배치가 아니라
  "앱 진입 시 마지막 확정일 이후를 소급 확정"하는 방식으로 구현한다.
- 2차 알림(취약 시간대)은 Capacitor Local Notifications로 처리. 서버 푸시 불필요.
- 개발 중에는 브라우저에서 바로 확인하고, 네이티브 빌드는 플러그인 검증 시에만 돌린다.

## 9. 성공 지표

| 지표 | 목표 (출시 4주) | 의미 |
|---|---|---|
| 첫 항목 생성률 | 첫 방문자의 70% | 온보딩이 충분히 가벼운가 |
| D7 리텐션 | 30% | 매일 열어볼 이유가 있는가 |
| 어김 기록 시 메모 작성률 | 40% | 기록이 성찰로 이어지는가 |
| 항목당 평균 유지 기간 | 14일 | 항목이 실제로 의미 있는가 |

핵심은 D7 리텐션이다. 하지 않기는 "매일 열어야 할 이유"가 약할 수 있다.
그래서 다음날 첫 진입 시 어제 요약(5.3)을 반드시 보여준다.

## 12. 결정 사항

- 시간/횟수 조건("밤 10시 이후", "30분 이하")은 지원하지 않는다. 했다/안 했다만 기록한다.
- Android + iOS 동시 출시, 웹앱을 Capacitor로 감싼 웹뷰 방식.
- 어김은 항목당 하루 1회. 여러 번 기록은 2차에서 검토.
- 어김 취소 기능은 없다. 확인 시트로 실수만 막는다.

## 13. 서비스 이름 후보

이름이 담아야 할 것: "오늘", "하지 않음", 그리고 가볍고 죄책감 없는 톤.

| 순위 | 이름 | 태그라인 | 왜 |
|---|---|---|---|
| 1 | **Not Today** | 오늘은 아니야 | 매일 아침 "오늘은 안 해"라고 선언하는 서비스 구조와 정확히 맞는다. 짧고, 발음 쉽고, 한국어 태그라인도 자연스럽다. 앱 열 때마다 하는 말이 곧 이름이다 |
| 2 | **안할일** | 할 일 말고 안 할 일 | 가장 직관적. "할일" 앱과 한 글자 차이라 컨셉 설명이 필요 없다. 스토어 검색에 유리. 단점은 밋밋함 |
| 3 | **낫투 (Notto)** | Not-Todo | Not Todo의 축약. 마스코트 만들기 좋고 기억에 남는다. 다만 발효식품과 발음이 같아 호불호 |
| 4 | **Won't** | I won't. | "할 것(will)"이 아니라 "안 할 것(won't)". 리스트 이름으로 "Won't List"도 성립. 영어권 확장 시 강함 |
| 5 | **말고** | 오늘은 그거 말고 | 한국어 고유 표현. "게임 말고", "야식 말고". 항목 이름 뒤에 붙이면 문장이 된다. 검색성은 약함 |

**추천: Not Today.**
- 서비스의 핵심 동작(아침 선언 → 하루 방어)이 이름 자체에 들어 있다.
- 어겼을 때의 카피도 이어진다: "오늘은 아니었네요. 내일은 Not Today."
- 스토어 표기는 "Not Today - 안 할 일 리스트"로 검색성을 보완한다.
- 출시 전 앱스토어/플레이스토어 동명 앱과 상표 검색 필요. 흔한 표현이라 도메인은 서브도메인이나 변형(nottoday.app 등)을 봐야 한다.

## 14. 디자인 방향

**이름 확정: Not Today** (태그라인: 오늘은 아니야)

### 14.1 무드보드

참고 이미지: `docs/moodboard/` (고양이와 스프 스타일. 레퍼런스일 뿐, 자산으로 쓰지 않는다.)

- 따뜻한 크림색 바탕, 세이지 그린과 소프트 레드의 포인트
- 손그림 느낌의 둥글고 두툼한 갈색 외곽선
- 작고 통통한 동물 캐릭터. 코스튬과 소품으로 성격 표현
- 아늑하고 느긋한 분위기. 긴장감이나 재촉이 없다

### 14.2 캐릭터 컨셉

**핵심 아이디어: Not-Todo 항목 하나가 캐릭터 하나다.**

사용자가 "야식 안 먹기"를 만들면, 그 항목을 지켜주는 작은 동물 친구가 생긴다.
하루 종일 지키면 캐릭터는 편안하게 지내고, 어기면 캐릭터가 반응한다.
사용자가 지키는 건 규칙이 아니라 **이 친구**다. 죄책감 대신 애착으로 동기를 만든다.

| 상태 | 캐릭터 |
|---|---|
| 지키는 중 (idle) | 편안히 앉아 있음. 숨쉬기, 눈 깜빡임, 가끔 기지개 |
| 탭 (확인 시트 열림) | 고개를 갸웃. "정말?" |
| 어김 확정 | 잠깐 움찔하고, 한숨 쉬고, 이불 덮고 눕는다. 그날은 잠듦 |
| 하루 방어 성공 (다음날 요약) | 폴짝 뛰며 좋아함 |
| 항목 생성 | 상자에서 톡 튀어나옴 |

원칙:
- **보상이 아니라 반응이다.** 방어 일수로 코스튬이 열리거나 레벨이 오르지 않는다 (4.3 참고).
  캐릭터는 항상 같은 모습으로 곁에 있고, 감정만 바뀐다.
- 어겼을 때 캐릭터가 화내거나 실망하지 않는다. 그냥 눕는다. 내일 다시 일어난다.
- 캐릭터 종류는 사용자가 항목 생성 시 고른다 (MVP 5종, 2차 확장). 항목 성격과 무관하게 취향으로 선택.

MVP 캐릭터 5종 (시안 필요, 무드보드 참고):
고양이, 강아지, 토끼, 곰, 고슴도치.
모두 같은 비율(2등신, 둥근 몸)로 통일해 한 화면에 여럿 있어도 균형이 맞아야 한다.

앱 대표 캐릭터(아이콘, 온보딩, 빈 화면)는 **고양이**.
고양이는 부르면 안 오고, 하기 싫으면 안 하는 동물이다. "오늘은 아니야"와 가장 잘 맞는다.

### 14.3 모션 원칙: 텐션

모든 움직임은 **스프링**이다. linear/ease-in-out 금지.

| 요소 | 모션 |
|---|---|
| 카드 등장 | 아래에서 튀어 올라 살짝 오버슈트 후 정착 (stiffness 높게, damping 중간) |
| 탭 | 눌리면 0.95로 찌그러지고(squash), 떼면 1.05로 튕겼다가(stretch) 복귀 |
| 확인 시트 | 바닥에서 스프링으로 올라옴. 배경은 살짝 어두워지며 카드들이 뒤로 물러남 |
| 어김 확정 | 카드가 한 번 흔들리고(shake), 색이 크림 → 소프트 레드로 번지듯 전환. 캐릭터 눕기 |
| 어제 요약 토스트 | 위에서 통통 튀며 등장. 방어 성공한 캐릭터들이 순서대로 폴짝 |
| 항목 생성 | + 버튼이 회전하며 입력창으로 변형. 저장하면 카드가 상자 열리듯 등장 |
| 숫자 변화 (방어율) | 카운트업. 숫자가 굴러가며 올라감 |
| 화면 전환 | 공유 요소 전환. 카드를 탭하면 그 카드가 커지며 상세 화면이 됨 |

구현:
- UI 모션은 Motion의 스프링 프리셋 하나를 정의해 전역에서 재사용 (`stiffness: 400, damping: 25` 근처에서 시작).
- 캐릭터는 Rive 상태머신. 웹뷰에서 60fps 유지되는지 저사양 Android에서 반드시 확인.
- 텐션은 있되 **빠르게 끝나야 한다.** 어떤 모션도 400ms를 넘기지 않는다. 기다리게 하면 텐션이 아니라 지연이다.
- 설정에 "모션 줄이기" 옵션. OS의 reduce motion도 존중.

### 14.4 컬러

무드보드에서 추출한 시작 팔레트. 캐릭터 시안이 나오면 조정한다.

| 역할 | 색 | 용도 |
|---|---|---|
| 배경 | `#FBF6EC` 크림 | 기본 화면 바탕 |
| 카드 | `#FFFDF7` 아이보리 | 항목 카드 |
| 외곽선/텍스트 | `#4A3728` 다크 브라운 | 검정 대신. 손그림 느낌 유지 |
| 지키는 중 | `#8FA98A` 세이지 | 방어 상태, 방어율 |
| 어김 | `#D9776B` 소프트 레드 | 어김 상태. 경고색이 아니라 볼 터치 느낌 |
| 포인트 | `#E8B84A` 머스터드 | 버튼, 강조 |
| 보조 | `#F2D4CE` 핑크 베이지 | 토스트, 배지 배경 |

다크 모드는 MVP에서 제외. 크림톤 자체가 눈에 편하고, 캐릭터 색이 다크 배경에서 죽는다.
