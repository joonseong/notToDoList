# Not To Do List — 서비스 기획서 (v0.1)

> "무엇을 할지"가 아니라 "무엇을 하지 않을지"를 정하고, 지켜냈는지 기록하는 서비스.

---

## 1. 문제 정의

Todo List는 "더 많이 하기"를 전제로 한다. 하지만 실제로 하루를 망치는 건
할 일을 못 한 것보다 **하지 말아야 할 행동을 반복한 것**인 경우가 많다.

- 자기 전 침대에서 숏폼 1시간
- 점심 먹고 습관적으로 커피 + 디저트
- 회의 중 노트북 열고 딴짓
- 퇴근 후 "잠깐만" 하고 게임 3시간

이런 행동은 Todo 앱에 넣을 수 없다. "하지 않기"는 체크박스로 표현되지 않고,
성공의 순간이 없기 때문이다. 하루가 끝나야 "안 했다"를 알 수 있다.

**핵심 인사이트**
1. 하지 않기는 "완료"가 아니라 **"하루 동안 유지"**의 개념이다.
2. 실패는 "안 함"이 아니라 **"해버림"**이다. 실패의 순간이 명확하다.
3. 그래서 UI의 기본 상태는 **"지키는 중"**이어야 하고, 사용자는 실패했을 때만 손을 댄다.

## 2. 타겟 사용자

| 페르소나 | 상황 | 하지 않고 싶은 것 |
|---|---|---|
| 직장인 A (29) | 퇴근 후 시간이 증발함 | 퇴근 후 유튜브 자동재생, 야식 배달 |
| 대학원생 B (26) | 집중력 관리가 과제 | 연구 중 SNS, 새벽 3시 이후 취침 |
| 프리랜서 C (34) | 일과 휴식 경계가 없음 | 주말에 슬랙 확인, 견적 없이 일 받기 |
| 자기계발형 D (31) | Todo 앱은 이미 씀, 습관 앱도 씀 | 충동구매, 남 험담 |

공통점: **이미 무엇을 하지 말아야 하는지 알고 있다.** 몰라서가 아니라 "선언하고 추적할 곳"이 없어서 못 지킨다.

## 3. 핵심 가치 제안

**"오늘 하지 않을 것을 아침에 선언하고, 밤에 지켜냈는지 확인한다."**

세 가지 차별점:

1. **역전된 체크박스** — 기본이 ✅(지키는 중). 사용자가 어기면 ❌로 바꾼다. 아무것도 안 하면 성공이다.
2. **연속 기록(Streak)이 아닌 "방어 일수"** — "N일째 안 함". 실패해도 0으로 리셋되는 대신 "이번 달 24/30일 방어"처럼 비율로 보여준다. 리셋의 좌절감을 줄인다.
3. **실패 기록이 데이터가 된다** — 어겼을 때 "언제, 왜(트리거)"를 한 줄로 남긴다. 축적되면 "나는 주로 밤 11시 이후, 피곤할 때 무너진다"가 보인다.

## 4. 기능 범위

### 4.1 MVP (1차 출시)

| # | 기능 | 설명 |
|---|---|---|
| F1 | Not-Todo 항목 생성 | 제목, (선택) 이유, (선택) 적용 요일 |
| F2 | 오늘 화면 | 오늘 적용되는 항목 목록. 기본 상태 "지키는 중" |
| F3 | 어김 기록 | 탭 한 번으로 "어겼음" 처리. 시각 자동 기록, 한 줄 메모 선택 |
| F4 | 어김 취소 | 실수 탭 대비. 당일 내 되돌리기 |
| F5 | 하루 마감 | 자정에 자동 확정. 어김 없으면 "방어 성공" |
| F6 | 항목별 통계 | 방어율(최근 7일/30일), 총 어김 횟수, 어긴 시간대 분포 |
| F7 | 항목 보관/삭제 | 더 이상 추적 안 하는 항목은 보관 (기록은 유지) |
| F8 | 로컬 우선 저장 | 로그인 없이 시작. 데이터는 기기에 저장 |

### 4.2 2차 (검증 후)

- 계정 + 동기화 (여러 기기)
- 리마인더: "취약 시간대"에 맞춰 알림 ("지금이 보통 무너지는 시간이에요")
- 주간 회고 카드: 이번 주 방어율, 가장 자주 어긴 항목, 주요 트리거
- 항목 템플릿: 자주 쓰는 Not-Todo 추천 (숏폼, 야식, 충동구매 등)
- 어김 시 "대신 한 것" 기록 (대체 행동 유도)

### 4.3 의도적으로 하지 않을 것 (이 서비스의 Not-Todo)

- **Todo 기능 추가** — 정체성이 흐려진다. 절대 넣지 않는다.
- **소셜/공유/랭킹** — 하지 않기는 사적인 영역. 비교는 동기가 아니라 수치심을 만든다.
- **게이미피케이션(뱃지, 레벨)** — 방어율이라는 단순한 숫자 하나면 충분하다.
- **긴 온보딩** — 첫 실행 후 30초 안에 첫 항목을 만들 수 있어야 한다.

## 5. 핵심 사용자 흐름

### 5.1 첫 실행
```
앱 실행 → "오늘 하지 않을 것 하나만 적어보세요" 입력창
→ 항목 생성 → 오늘 화면 (항목 1개, 상태: 지키는 중)
```

### 5.2 하루 중
```
오늘 화면 진입 → 모든 항목 "지키는 중"
→ (어겼을 때) 항목 탭 → "어겼어요" 확인 → (선택) 한 줄 메모
→ 항목 상태 ❌ + 시각 표시
```

### 5.3 하루 마감
```
자정 → 당일 기록 확정
→ 다음날 첫 진입 시 어제 요약 토스트: "어제 3개 중 2개 방어"
```

### 5.4 통계 확인
```
항목 탭 → 상세 화면
→ 방어율 (7일 / 30일), 최근 어김 목록 (시각 + 메모), 시간대 히트맵
```

## 6. 화면 구성

| 화면 | 주요 요소 |
|---|---|
| **오늘(Today)** | 날짜, 오늘 방어 현황(2/3), 항목 카드 리스트, + 버튼 |
| **항목 카드** | 제목, 상태(지키는 중 / 어김 HH:MM), 방어 일수 뱃지 |
| **어김 기록 시트** | "정말 어겼나요?" 확인, 한 줄 메모, 저장 |
| **항목 상세** | 방어율, 어김 히스토리, 시간대 분포, 편집/보관 |
| **항목 편집** | 제목, 이유, 적용 요일, 보관/삭제 |
| **전체 통계** | 이번 달 종합 방어율, 항목별 랭킹, 취약 시간대 |
| **설정** | 하루 시작 시각(예: 새벽 4시 기준), 테마, 데이터 내보내기 |

UI 원칙:
- 기본 화면은 조용해야 한다. 지키고 있으면 아무 일도 안 일어난다.
- 어김 처리는 1탭 + 1확인. 죄책감을 주는 카피 금지. ("괜찮아요, 기록했어요")
- 색상: 지키는 중 = 중립(회색/차분한 톤), 어김 = 눈에 띄되 공격적이지 않게.

## 7. 데이터 모델

```
NotTodo
  id            string (uuid)
  title         string
  reason        string?         // 왜 하지 않으려는지
  activeDays    int[]           // 0(일)~6(토), 비어있으면 매일
  createdAt     datetime
  archivedAt    datetime?

Violation                        // 어김 기록
  id            string
  notTodoId     string
  occurredAt    datetime
  note          string?
  trigger       string?         // 2차: 태그 (피곤함, 스트레스, 심심함...)

DailyRecord                      // 하루 마감 시 확정 (통계 캐시)
  date          date
  notTodoId     string
  defended      boolean
  violationCount int
```

- "오늘"의 기준은 자정이 아니라 사용자가 설정한 **하루 시작 시각** (기본 04:00).
  새벽 1시의 어김은 "어제"로 기록되어야 자연스럽다.
- `DailyRecord`는 파생 데이터. `Violation`으로부터 언제든 재계산 가능해야 한다.

## 8. 기술 스택 (제안)

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | Next.js (App Router) + TypeScript | 웹 우선 출시, PWA로 모바일 홈화면 대응 |
| 스타일 | Tailwind CSS | 빠른 프로토타이핑 |
| 상태/저장 | Zustand + IndexedDB (Dexie) | MVP는 로컬 우선, 로그인 없음 |
| 2차 백엔드 | Supabase (Auth + Postgres) | 동기화 도입 시 최소 비용 |
| 배포 | Vercel | |
| 테스트 | Vitest + Playwright | 날짜 경계(하루 시작 시각) 로직은 유닛 테스트 필수 |

MVP는 **PWA 웹앱**으로 시작한다. 앱스토어 심사 없이 빠르게 검증하고,
반응이 있으면 네이티브(Expo)로 확장한다.

## 9. 성공 지표

| 지표 | 목표 (출시 4주) | 의미 |
|---|---|---|
| 첫 항목 생성률 | 첫 방문자의 70% | 온보딩이 충분히 가벼운가 |
| D7 리텐션 | 30% | 매일 열어볼 이유가 있는가 |
| 어김 기록 시 메모 작성률 | 40% | 기록이 성찰로 이어지는가 |
| 항목당 평균 유지 기간 | 14일 | 항목이 실제로 의미 있는가 |

핵심은 D7 리텐션이다. 하지 않기는 "매일 열어야 할 이유"가 약할 수 있다.
그래서 다음날 첫 진입 시 어제 요약(5.3)을 반드시 보여준다.

## 10. 리스크와 대응

| 리스크 | 대응 |
|---|---|
| 지키고 있을 때 앱을 열 이유가 없음 | 어제 요약 토스트, 2차에서 취약 시간대 알림 |
| 어김을 솔직하게 기록하지 않음 | 죄책감 없는 카피, 방어율(비율)로 리셋 공포 제거 |
| 항목을 너무 많이 만들어 포기 | 동시 활성 항목 5개 권장 (소프트 제한, 경고만) |
| 습관 앱과의 차별성 부족 | 역전된 체크박스 + 어김 트리거 분석에 집중 |

## 12. 열린 질문 (결정 필요)

1. **하루에 여러 번 어길 수 있는가?** 
   - 안: 횟수 기록 (야식 2번). 통계는 "어긴 날" 기준으로 계산.
2. **"조건부 Not-Todo"를 지원할 것인가?** (예: "밤 10시 이후 폰 보지 않기")
   - 안: MVP는 제목에 자연어로만. 2차에서 시간 조건 필드 추가.
3. **어김 취소 가능 기간** — 당일만? 3일까지?
   - 안: 당일(하루 시작 시각 기준)까지만. 데이터 정직성 유지.
4. **이름** — "Not Todo", "안 할 일", "Don't", "Undo List" 등. 브랜딩 별도 논의.
